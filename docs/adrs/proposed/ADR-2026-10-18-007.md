# Extrair BaseSelectField.vue para eliminar duplicação de CSS de select entre modais

## Contexto

O Finding `ARCH-014` identifica que o padrão visual de campo `<select>`
(esconder a seta nativa via `appearance: none` e desenhar uma seta
customizada) é reimplementado em CSS scoped duplicado em pelo menos três
modais de entidade: `ModalNovoLancamento.vue:259` (classe `.select`),
`ModalNovaConta.vue:125` (classe `.fi-sel`) e `ModalNovoMembro.vue:89`
(classe `.fi-sel`) — cada um com seu próprio bloco `-webkit-appearance:
none; appearance: none;` repetido.

Essa dependência de copiar-colar já falhou na prática: `ModalNovaCategoria.vue:50`
usa `<select class="fi fi-sel">`, mas o `<style scoped>` desse arquivo
(a partir da linha 202) nunca define `.fi-sel` — só existe `.fi` (linha
208) e um seletor `div > .fi`. O resultado é um `<select>` sem o CSS que
esconde a seta nativa do navegador, um defeito visual direto causado pela
ausência do bloco que deveria ter sido copiado.

## Decisão proposta

Extrair um componente `BaseSelectField.vue` que encapsule o CSS de
aparência do select (reset da seta nativa, seta customizada, estados de
foco/placeholder) e seja reutilizado por todos os modais de
criação/edição de entidade (`ModalNovoLancamento`, `ModalEditarLancamento`,
`ModalNovaConta`, `ModalNovoMembro`, `ModalNovaCategoria`, e demais que
usem o mesmo padrão). Isso elimina a necessidade de copiar o bloco CSS a
cada novo modal e corrige o select não estilizado de
`ModalNovaCategoria.vue` como efeito colateral direto da extração, sem
exigir um fix isolado para esse caso específico.

Alternativa considerada: corrigir apenas o CSS ausente em
`ModalNovaCategoria.vue` (adicionar o bloco `.fi-sel` faltante) sem extrair
componente. Essa alternativa resolve o sintoma imediato, mas não resolve a
causa — qualquer novo modal futuro continuaria sujeito ao mesmo erro de
copiar-colar incompleto. A extração de `BaseSelectField.vue` é a
recomendação.

## Consequências

Melhora: uma única definição de CSS de select, eliminando a classe de bug
observada em `ModalNovaCategoria.vue` e qualquer repetição futura do
mesmo erro em novos modais.

Custo: migrar os cinco+ modais existentes para o novo componente exige
tocar cada um deles e seus respectivos testes (`ModalNovoLancamento.test.ts`,
`ModalEditarLancamento.test.ts`, `ModalNovaCategoria.test.ts`, e os testes
dos modais de conta/membro), sem remover cobertura equivalente, conforme a
Regra de Ouro do projeto.

Risco de a extração do componente introduzir uma diferença de
comportamento de acessibilidade (ex. `aria-label`) entre os selects
atuais, que têm atributos distintos por modal: Evidence unavailable.
