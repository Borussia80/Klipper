# Extrair componente compartilhado para o padrão de campo com select

## Contexto

O Finding `ARCH-014` (`modal-field-css-duplicated-across-entity-modals`)
aponta que o padrão visual de campo com `<select>` — classes `.fi`/`.fi-sel`
com `-webkit-appearance: none; appearance: none;` e estilização customizada
da seta — está reimplementado em CSS `scoped` duplicado em pelo menos 8
arquivos de `apps/klipper-web`: `components/ui/ModalNovaConta.vue`,
`components/ui/ModalNovoMembro.vue`, `components/ui/ModalEditarReembolso.vue`,
`components/ui/ModalNovoLancamento.vue`, `components/ui/ModalEditarLancamento.vue`,
`components/ui/DataHealthBanner.vue`, `pages/importar.vue` e
`pages/relatorios.vue`.

A evidência observada no checkout confirma a duplicação: em
`components/ui/ModalNovaConta.vue` o bloco aparece como

```css
.fi-sel {
  -webkit-appearance: none;
  appearance: none;
  ...
}
```

enquanto em `components/ui/DataHealthBanner.vue` o mesmo par de classes
reaparece sob um wrapper diferente (`.sel-wrap .fi-sel { -webkit-appearance:
none; appearance: none; cursor: pointer; ... }`), e em `pages/importar.vue`
o bloco `.fi-sel { -webkit-appearance: none; appearance: none; ... }` é
reescrito uma terceira vez. Segundo o histórico do finding, a superfície de
duplicação cresceu de pelo menos 3 para 8 arquivos entre a primeira e a
última auditoria (2026-09-17 → 2026-09-18), com `importar.vue` e
`DataHealthBanner.vue` sendo as adições mais recentes — ou seja, a feature
mais nova já reproduziu a duplicação em vez de reaproveitar um componente
existente.

## Decisão proposta

Extrair o padrão de campo com select em um componente compartilhado
`components/ui/BaseSelectField.vue`, que encapsule o markup (`label` +
wrapper + `select` estilizado) e o CSS hoje duplicado como `.fi`/`.fi-sel`,
recebendo `label`, `v-model` e `options` (ou slot de `<option>`) como
interface pública.

Alternativa considerada: mover apenas o CSS para uma classe utilitária
global em `assets/css` (sem componente Vue), mantendo o markup do `<select>`
em cada arquivo. Essa alternativa resolve a duplicação de estilo mas não a
duplicação de markup/acessibilidade (ex: `aria-label`, estrutura do wrapper
`.sel-wrap`), que também se repete.

Recomenda-se o componente `BaseSelectField.vue` em vez da classe utilitária
isolada, priorizando primeiro a migração de `pages/importar.vue` e
`components/ui/DataHealthBanner.vue` — os dois usos mais recentes — antes
que o padrão duplicado se torne convenção implícita para novas features.

## Consequências

Migrar os 8 arquivos para `BaseSelectField.vue` centraliza qualquer ajuste
futuro de estilo ou acessibilidade do padrão de select em um único lugar,
eliminando divergências como a já observada entre `.fi-sel` "solto" (em
`ModalNovaConta.vue`) e `.fi-sel` sob `.sel-wrap` (em `DataHealthBanner.vue`).
O custo é o esforço de migração em 8 pontos de uso e a necessidade de
validar que a interface do novo componente cobre variações já existentes
(ex: `.fi { margin-bottom: 0; }` em `pages/importar.vue` versus
`margin-bottom: 16px` em `ModalNovaConta.vue`), sob risco de regressão
visual pontual se essas variações não forem preservadas via prop.

Evidence unavailable para impacto em performance de build ou em tempo de
carregamento — o finding e o código observável não fornecem base para essa
avaliação.
